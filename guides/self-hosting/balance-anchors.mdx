---
title: Linked-account balance anchoring
description: Control how Sure handles stale provider-reported balance readings on linked accounts
---

Linked accounts can accumulate unwanted "Manual balance update" entries when a provider reports a balance early in the day and transactions that explain the move are imported later. The `BALANCE_REUSE_EXPLAINED_ANCHOR` environment variable controls whether Sure removes these unnecessary waypoints.

## Default behavior

When `BALANCE_REUSE_EXPLAINED_ANCHOR` is unset or set to any value other than `1`, `true`, or `yes`, Sure preserves every stale provider-reported balance reading as a reconciliation waypoint. This matches the behavior of all versions prior to this change and is safe to leave in place.

## Enabling explained-anchor reuse

Set `BALANCE_REUSE_EXPLAINED_ANCHOR=1` (or `true` or `yes`) in your environment to enable the new behavior.

When the flag is on, Sure compares each stale reading against the transactions imported in the same sync. If the imported ledger fully explains the move to the provider's new reading, the anchor is updated in place rather than frozen as a waypoint. If it does not explain the move — because the provider knew something the ledger does not — the old reading is preserved as a reconciliation waypoint and a new anchor is created for today.

The result for a healthy linked cash account is one live `current_anchor` row and no system-generated "Manual balance update" entries.

Only cash (`depository`) accounts are evaluated. Investment accounts keep the existing behavior.

## Rollout and rollback

**Before enabling the flag:**

- Take a database backup.
- Record a baseline of your daily balance charts, since they may shift on the first reverse sync after enabling.

**After enabling:**

- On the first sync after the flag is set, materialized balance rows are recalculated. Historical chart values may move to corrected values.
- Existing reconciliation rows created by prior rotations are retained. Sure cannot distinguish a sync-created waypoint from a genuine user reconciliation, so there is no automatic historical repair.

**Disabling the flag** restores the old preserve-every-stale-anchor behavior for future syncs. It does not restore an anchor that was overwritten while the flag was enabled. Reverting the code has the same limitation.

## Known limitations

- The single live `current_anchor` is still visible in the activity feed as "Current balance."
- Accounts with occasional foreign-currency transactions may land in the preserve branch more often than expected because cross-currency moves cannot be compared directly.
- For providers (such as Plaid credit accounts) that report a balance including pending transactions, the ledger comparison uses confirmed transactions only, so those accounts may still produce waypoints more often.
