## Overview

Insights are short, actionable observations about your finances that Sure generates nightly. Each insight spots a pattern or event in your data — a spending anomaly, a milestone crossed, a budget running over — and fills a plain-language summary from a template so you understand what changed and why.

Insights appear in the dashboard feed.

## Insight types

| Type | What it flags |
|---|---|
| `spending_anomaly` | A category's projected month-end spend deviates 25 %+ from the three-month average baseline (above or below). Projection uses the full calendar month length, not just elapsed days, so an on-pace category is never flagged as a shortfall. Only fires after 7 days into the month. |
| `cash_flow_warning` | Projected cash balance may drop below a safe threshold within the next 30 days |
| `net_worth_milestone` | Net worth has crossed a round-number milestone within the last 30 days |
| `subscription_audit` | A recurring transaction has not appeared since its expected due date, by at least one full billing cycle |
| `savings_rate_change` | Savings rate has shifted materially compared to recent months |
| `idle_cash` | A cash account has a large balance that has been untouched for 60+ days |
| `budget_at_risk` | Budget categories are near or over their monthly limit |
| `budget_on_track` | All budget categories are on track (shown after the month is at least half over) |
| `maintained_goal_depleted` | A reserve goal has fallen below its target balance |

## Priority

Each insight carries one of three priority levels:

- **High** — requires prompt attention (e.g. significantly over budget)
- **Medium** — worth reviewing soon
- **Low** — a gentle nudge (e.g. idle cash)

The dashboard feed and API response order insights by priority first, then by recency.

## Statuses

| Status | Meaning |
|---|---|
| `active` | New — not yet seen |
| `read` | Viewed but not dismissed |
| `acknowledged` | Dismissed by the user |
| `expired` | The underlying condition cleared; no longer shown in the feed |

`active` and `read` insights appear in the feed. Acknowledged insights can be unacknowledged — this restores them to `read` without treating them as new.

## Accessing insights

On desktop, the Insights button appears in the left navigation sidebar. On mobile, the button appears on the left side of the top navigation bar, next to the account sidebar toggle. It shows an unread badge with a count of active insights you haven't viewed yet. The badge updates live: it decrements when you dismiss an insight, increments when you undo a dismissal, and updates when newly generated insights arrive — without requiring a page navigation. Tapping or clicking the button opens the full insights feed and marks all active insights as `read`.

The Insights button is only shown when preview features are enabled for your account.

## Family feed and account privacy

The insights feed is shared across the whole family. An insight that names a specific account — such as an idle cash nudge — appears in the feed only while every active family member can access that account. If account sharing is revoked, a member joins the family, or the account is hidden or deleted, the insight is hidden on the next feed read if the visibility condition no longer holds. Restoring access can make it visible again if it is still active or read, rather than dismissed or expired.

The idle cash generator only considers accounts every active member can see. A private account is excluded when another active family member lacks access. In a family with only one active member, an account owned by that member can qualify without a share.

## Dashboard feed

The dashboard shows the three highest-priority, unacknowledged insights. Clicking an insight marks it `read`. Dismissing it marks it `acknowledged`.

## Dig in with AI

Each insight card has a **Dig in with AI** button that opens the assistant sidebar with a pre-filled message summarising the insight — its title, body, period, and key figures. You can edit the message before sending it.

The button is shown when:

- The family's assistant is enabled
- An LLM provider is configured (or an external assistant is set up)

Clicking the button prefills the chat input; it does not send the message automatically.

### Customizing the dig-in prompt

Family admins can replace the default first message from **Settings → AI Prompts** under the **Insight Dig In** section. The override supports four placeholders:

| Placeholder | Value |
|---|---|
| `%{title}` | Insight title |
| `%{body}` | Insight body text |
| `%{period}` | Display period (e.g. "Oct 1 – Oct 31") |
| `%{facts}` | Key figures as a bulleted list |

Any other `%{...}` sequences are left as typed. Clearing the field restores the default message.

## Language

Insight bodies are filled from i18n templates in your family's locale. The template is interpolated with the generator's pre-computed figures, so no LLM call is made when creating or refreshing an insight. If no locale is set, Sure defaults to English.

## API access

You can read your family's insights via the API:

- `GET /api/v1/insights` — list all visible insights

Push notification device tokens are managed separately:

- `POST /api/v1/push_subscriptions` — register a device token
- `DELETE /api/v1/push_subscriptions/{id}` — unregister a device token

### Push subscription registration

The registration endpoint accepts an optional `device_key` — a 64-character lowercase hex string that identifies a specific app installation. Include it when your app generates a stable per-install identifier (for example, a UUID stored in the keychain, hex-encoded).

When a token arrives with a `device_key`, Sure compares a SHA-256 digest of that key against the value stored for the existing subscription. If the digests match, the subscription transfers to the new user. If they do not match, registration is rejected with a `validation_error` to prevent one user from claiming another user's device.

Call `DELETE /api/v1/push_subscriptions/{id}` before the user signs out so the old subscription is cleaned up before a new one is created.

### Delivery behavior

Push notifications for high-priority insights are delivered only on the hosted version of Sure. The server retries on transient APNs errors (HTTP 429 and 5xx responses) with exponential back-off up to five attempts. A 410 response from APNs means the token is permanently unregistered; Sure removes the subscription only if the token has not been re-registered since the APNs invalidation timestamp, so a prompt re-registration from the device is never incorrectly removed.

Subscriptions inactive for more than 90 days are excluded from all deliveries.
