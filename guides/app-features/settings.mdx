# Settings

Sure provides various settings to customize your experience and control how the app behaves.

## Security settings

### High-resolution logos

Sure can fetch high-resolution logos for merchants, financial institutions, and cryptocurrencies using the Brandfetch service. This feature enhances the visual appearance of your transactions, accounts, and holdings.

**To enable high-resolution logos:**

1. Navigate to Settings → Security
2. Scroll to the "Brandfetch Settings" section
3. Toggle "Use high-resolution logos" to enable
4. The setting saves automatically

When enabled, Sure will:
- Show each bank sync provider's own brand icon on Bank Sync cards, drawers, and Accounts connection cards
- Fetch higher quality logos for merchants and institutions
- Display dedicated logos for cryptocurrency assets (e.g., BTC, ETH) via Brandfetch's crypto logo service
- Use Brandfetch as a fallback for stock tickers when logos aren't available
- Display clearer, more professional-looking icons throughout the app

<Note>
High-resolution logos may increase data usage slightly as larger image files are downloaded.
</Note>

### Brandfetch integration

The Brandfetch integration provides:
- **Provider logos**: Each bank sync provider's own icon on Bank Sync cards and Accounts connection cards, falling back to a generic icon or initials when unavailable
- **High-quality logos**: Professional brand assets for better visual recognition
- **Cryptocurrency logos**: Dedicated logo resolution for crypto assets using per-coin identifiers
- **Fallback support**: Automatic logo lookup for stock tickers and merchants
- **Consistent branding**: Standardized logo appearance across all transactions and holdings

This feature works automatically once enabled. Self-hosted users must also set the `BRAND_FETCH_CLIENT_ID` environment variable. See [self-hosting configuration](/self-hosting#brand-logo-variables) for details.

## API keys

Generate API keys for programmatic access to your Sure data from **Settings → API Keys**. Each key carries a permission scope — Read Only or Read/Write — and is authenticated using the `X-Api-Key` request header.

See [API keys](/guides/app-features/api-keys) for details on creating keys, scopes, and rate limits.

Add passkeys, Touch ID, Windows Hello, or hardware security keys from **Settings → Security** after enabling 2FA. These credentials can be used to sign in without email/password when passkey login is enabled, or as the second factor after email/password sign-in.

See [Passkeys and security keys](/guides/app-features/passkeys) for setup steps and self-hosting configuration notes.

## Bank sync settings

Configure third-party bank, brokerage, crypto, and data sync integrations from Settings → Bank sync. See the [providers documentation](/providers/overview) for detailed setup instructions.

### Syncing from the Accounts page

The **Accounts** page has a sync control in the header that lets you trigger and manage a family-wide sync without leaving the page.

- When no sync is running, a refresh icon button is shown. Click it to start a sync of all connected accounts.
- When a sync is in progress, the refresh icon becomes a spinning indicator and is disabled. A **Cancel sync** button also appears next to it.
- Clicking **Cancel sync** requests cancellation and shows a confirmation notice. Work already running may finish before the sync stops.

Sure triggers a family-wide sync automatically on login when `auto_sync_on_login` is enabled and the family has not synced yet today. When this auto-sync is in progress as you navigate to the Accounts page, the sync controls reflect the in-progress state immediately.

## Classifier

Sure includes a built-in Bayes category classifier that learns from your categorized transactions and automatically categorizes new ones. It runs before any AI provider, so it handles common patterns quickly without an LLM call. Go to **Settings → Classifier** to configure it.

### Category classifier and merchant matcher rules

The classifier and the merchant matcher each run as a rule in your rule order. Every family gets two rules created automatically:

- **Category classifier** — categorizes uncategorized, unlocked transactions after each sync.
- **Merchant matcher** — fills in missing merchants by copying from near-duplicate descriptions (for example, matching "NETFLIX.COM 8812" to "Netflix com").

You can move, disable, or delete these rules on the Rules page. The switches on Settings → Classifier turn the corresponding rule on and off. If you delete a rule and want it back, the toggle will prompt you to add it again.

### Classifier settings

**Threshold** — the minimum confidence score (0.05–0.99) Bayes must reach before applying a category. Lower values categorize more transactions but produce more mistakes. Higher values leave more transactions for your AI provider.

**Lock the categories the classifier sets** — when enabled, the classifier locks categories it writes, so other rules and syncs cannot change them. AI never changes Bayes-locked categories regardless of this setting. You can still override a lock by clicking Apply on a rule manually.

### Merchant matcher settings

**Similarity** — the minimum description similarity (0.5–0.99) required before the matcher copies a merchant. Lower values fill in more merchants but introduce more mistakes.

**Lock the merchants the matcher sets** — when enabled, the matcher locks merchants it writes, so subsequent rules, AI, and syncs cannot change them.

**Advanced tuning** — under Merchant matcher tuning you can adjust the cutoff (how common a word must be across source transactions before it is ignored as a signal), the number of near-duplicates that must agree, and whether the matcher skips its own recent unconfirmed results to avoid feedback loops.

### Training settings

**Categories** — choose which categories the classifier learns from and can assign. Unchecked categories (and their subcategories) are excluded from training entirely. Use this to prevent the classifier from guessing rarely-used or internal categories.

**Training transactions** — how many of your newest transactions (100–20,000) to use as training data for both the classifier and the matcher.

**Exclude transfers** — transfers and inter-account payments are left out of training by default so they do not distort category patterns.

**Don't learn from Bayes' own guesses until confirmed** — prevents the classifier from training on its own unconfirmed output. A transaction is treated as confirmed when you change or lock its category. One left alone for the configured number of days counts as accepted.

### Auto-tune

The auto-tune panel scores your current settings against your transaction history and can search for better ones.

**Test my settings** — classifies each of the last several months as if they were new, using only the history before each month. Produces a table comparing your settings, the best found, and the defaults across accuracy metrics for the category classifier and the merchant matcher.

**Find best settings** — searches the older months by ROC-AUC to find higher-scoring settings, then shows results on the months it did not use for the search. A change is kept only when it improves the overall score and holds up in all but one individual month. Requires enough transaction history (roughly the number of months shown in the hint); if there is too little history, Apply leaves those settings unchanged.

**A mistake costs** — adjusts which threshold the bold cells highlight and which settings Apply will use. Higher values trade fewer wrong categorizations for more left uncategorized.

**Apply these settings** — saves the best-found settings to your classifier. Disabled when the test results are stale (settings changed since the last run) or when nothing scored better than your current settings.

**Reset to defaults** — reverts every classifier setting to the original multinomial naive Bayes defaults and immediately tests them.

### Clearing Bayes locks

Use **Clear Bayes locks** (on the Classifier page) to unlock all categories the classifier locked and all merchants the matcher locked that are still set to what they wrote. The categories and merchants themselves are kept; only the lock is removed, allowing rules, AI, and syncs to change them again.

## Preferences

### Count investing as spending

By default, investment contributions from a non-investment, non-crypto account into an investment or crypto account count as spending in budgets, reports, the savings rate, and the cash flow Sankey. Transfers between investment or crypto accounts remain funds movements. Existing account and transaction exclusions still apply, including accounts excluded from reports and tax-advantaged accounts.

If your household treats contributions to an ISA, pension, or brokerage as saving rather than spending, you can turn this off. Go to **Settings → Preferences** and toggle **Count investing as spending** to off (requires admin role). When the setting is off:

- Investment contributions no longer appear in spending totals or budget actuals.
- The cash flow Sankey draws a separate **Invested** outflow node next to Surplus or Deficit.
- The AI assistant's income statement reports an `invested` total alongside income and expenses.
- Budget drilldowns and report breakdowns exclude those transactions.
- Loan payments are unaffected and remain counted as expenses.


The preference is part of the income statement cache key, so a new report request uses the updated setting.

## Preview features

Some newer areas of the app are gated behind preview features while they are still rolling out.

### Goals section

The Goals section is gated behind preview features. To access it, enable **Preview features** in your preferences.

1. Navigate to Settings → Preferences
2. Turn on **Enable preview features**
3. Refresh the app if the Goals section does not appear immediately

Once enabled, Goals appears in the main navigation. See [Goals](/guides/app-features/goals) for full details.

#### Reserve target: months of expenses

When creating or editing a maintained goal (such as an emergency fund), you can set the target balance as a number of months of your household's spending rather than a fixed amount.

**To use a months-based target:**

1. Create or open a maintained goal.
2. Under **Target balance**, choose **Months of expenses** instead of **Fixed amount**.
3. Enter the number of months (for example, 3 or 6).
4. Sure calculates the target balance from your family's median monthly spending and saves it immediately.

Sure recalculates and updates the target balance on the 1st of each month so it stays current as your spending changes. If your family has no spending history yet, the form keeps a manual entry field so you can set an initial target balance directly. Once spending history is available, the form shows the calculated figure instead of a text input.

Changing the number of months or switching back to a fixed amount updates the target balance right away.

#### Funding accounts and earmarks

When you create or edit a goal, each eligible depository account shows how much of its balance is still available to earmark.

- Leave the amount field blank to dedicate that account's whole balance to the goal. The field shows the placeholder **"Blank: whole balance"** so it is clear that an empty field is a deliberate choice, not an unfilled value.
- Enter a specific amount to reserve only that portion, leaving the rest available for other goals.

The hint beneath each account row tells you what the goal will claim when the amount is left blank:

- If no other goal has earmarked any portion of that account, the hint reads **"This goal will use this account's whole balance."**
- If other goals already hold earmarks on the same account, the hint reads **"This account will fund whatever is left after the other earmarks."**

If your goals on the same account add up to more than its balance, Sure shows a message explaining that they will progress pro rata — it is not an error. A goal in progress legitimately claims more than its account currently holds.

When another goal already holds a whole-account link on an account, that account shows as unavailable. You must enter a specific amount to add it to a second goal.

#### Linking accounts to a goal

When you link an account to a goal, you can either dedicate the account's entire balance to that goal or earmark a fixed amount. An account's full balance can only be dedicated to one active goal at a time. If another active goal already claims an account in full, Sure asks you to enter a specific amount instead of claiming the whole balance. This prevents the same money from being counted toward two goals simultaneously.

If you archive a goal that claimed an account in full, that account becomes available for another goal to claim in full. Restoring the archived goal while the account is already claimed in full by another goal will fail with a message identifying the conflicting goal. To restore it, either update the conflicting goal to use a fixed amount, or restore the archived goal and set a fixed amount on that account link.

#### Completing a goal

When a goal reaches its target, a celebration panel appears on the goal's page. For one-off goals (goals with a fixed target you save toward once), the panel offers a **Close** action. Closing a goal does two things:

- **Releases the earmark** — the money the goal was reserving on your linked accounts is freed. Other goals sharing those accounts can now claim that balance.
- **Freezes the reached amount** — the figure is stamped at the moment you close the goal, so spending from those accounts afterward does not walk the goal's history back.

Until you explicitly close a reached goal, it continues to reserve its earmark and compete with sibling goals on the same accounts.

Maintained goals (reserves you hold indefinitely, such as an emergency fund) are never asked to close. A maintained goal at 100% is in its normal state and keeps its reservation.

A closed goal can be reopened from the kebab menu, which thaws the frozen amount and returns the goal to active status.

#### Archiving a goal

Archiving moves a goal off the active list. An archived goal releases its earmark — any accounts it claimed in full become available to other goals. If you later unarchive a goal, Sure checks whether another goal has since claimed one of its whole-account links. If so, the restore fails with a message identifying the conflicting goal and account, so you can resolve the overlap manually.

#### Deleting a goal

You can delete a goal directly from the goal's page using the **Delete** option in the kebab menu — no need to archive it first. The confirmation dialog describes exactly what will be removed (linked accounts and pledges). Deleting a goal does not affect your transactions or account balances.

### New Sankey cash flow chart

A redesigned Sankey cash flow chart is available as a preview feature on the dashboard. It uses a shared API with the mobile Swift client, making the web and mobile charts consistent.

To access it, enable **Preview features** in your preferences (Settings → Preferences → Enable preview features).

When preview features are enabled, the new chart appears below the existing cashflow visualization on the dashboard under the label **New Sankey chart**. You can expand it into a full-screen dialog using the expand button in the chart header.

The preview panel includes a feedback prompt so you can compare the new chart against the original and report any differences. If Sure detects that the two charts produce different financial totals, the "Something looks wrong" button highlights automatically. Submitting feedback opens a short form — describe the issue without including account numbers or balances, as responses are sent to PostHog.

**Label display:** The chart labels nodes in order of size — larger categories claim their labels first when space is limited. A small node positioned above a large one no longer causes the larger category's label to be hidden. If two nodes are the same size, the one higher in the chart takes priority. On narrow screens, a label that would extend across into a neighboring column's bar is hidden so it does not cover other categories. Hidden labels remain visible on hover.

**Sort flows:** A "Sort flows" control lets you change the vertical ordering of nodes in each column of the chart. Three options are available:

- **Auto** — uses d3-sankey's default layout, which minimises crossing lines between nodes.
- **Smallest first** — orders nodes from smallest amount at the top to largest at the bottom.
- **Largest first** — orders nodes from largest amount at the top to smallest at the bottom.

Your choice is saved in the browser and applies to both the inline chart and the expanded full-screen view, keeping them in step.

**Show flows by category or account:** A "Show flows by: Category / Account" toggle appears in the Sankey chart header. The default category view routes money through a single Cash Flow node. The account view routes income categories through each individual account to expense categories. An account that takes in more than it spends feeds Surplus; an account that spends more than it takes in (for example, a credit card paid off by a transfer) is fed from Deficit. Transfers between accounts do not appear as flows. The choice is saved as a preference and the chart updates without a page reload.

## Appearance settings

### Dashboard layout

You can customize how your dashboard is displayed:

**Hide and show widgets**: Enter Customize mode by clicking the layout icon in the dashboard header. In Customize mode, each widget shows a hide button. Clicking it removes the widget from your dashboard. A panel at the bottom of the page lists all hidden widgets so you can add them back at any time. Click **Done** to exit Customize mode. Hidden widgets and their date ranges, account filters, and other settings are preserved while hidden.

If you hide all widgets, the dashboard shows an empty state with a link back to Customize mode.

**Reorder widgets**: Drag widgets into any order. Hover over a widget to reveal the drag handle (grip icon) in its header, then drag to reposition. On touch devices, press and hold a widget for about 800 ms before dragging. With a keyboard, press **Enter** or **Space** to grab a focused widget, use **Up** and **Down** to move it, and press **Enter**, **Space**, or **Escape** to release. The new order is per-user and saves on drop or keyboard release.

**2-column layout**: On wide screens, display dashboard cards in a 2-column grid for better space utilization. This setting is available in Settings → Appearance.

When enabled:
- Dashboard cards arrange in two columns on desktop screens
- Provides a more compact view of your financial overview
- Automatically adjusts to single column on mobile devices

**Start expanded by default**: Choose which account groups open automatically when the dashboard and account sidebar load. Available in Settings → Appearance → Dashboard.

You can select any combination of the nine account group types: Cash, Investments, Crypto, Property, Vehicles, Credit Cards, Loans, Other Asset, and Other Liability. Groups you check here start open on every page load. You can still collapse them manually at any time — the preference only controls the initial state, not any changes you make during the session.

### Account order

Control how accounts are sorted within each group in the sidebar and the dashboard balance sheet. Go to **Settings → Appearance** and choose a **Default account order**:

- **Name (A-Z)** — alphabetical ascending (default)
- **Name (Z-A)** — alphabetical descending
- **Balance (Low to High)** — smallest balance first
- **Balance (High to Low)** — largest balance first
- **Manual (drag to reorder)** — arrange accounts yourself

When you select **Manual**, a **Sort accounts** button appears at the top of the accounts sidebar. Click it to enter sort mode. In sort mode you can:

- **Mouse**: drag any account row to a new position within its group
- **Touch**: drag rows on touch devices
- **Keyboard**: press **Enter** or **Space** to grab a focused row, use **Up** and **Down** to move it, then press **Enter**, **Space**, or **Escape** to release

The order is saved per account type group and per user. Accounts you add later appear after your arranged ones, sorted alphabetically.

The manual order also applies to the dashboard balance sheet. If you navigate away while holding a row with the keyboard, Sure saves the move before continuing so the new page reflects your change.

### Drag to select a date range on charts

You can select a custom date range directly on the net worth chart or on any account's balance chart by clicking and dragging across it. Releasing the mouse navigates the page to that range. The period picker updates to show the selected dates (for example, "Aug 15 – Sep 5") instead of a generic "Custom" label. Choosing a preset from the picker clears the custom range. Drag-select is mouse-only; on touch devices, swiping the chart scrolls normally.

### Spending widget

The dashboard includes a **Spending** widget that shows your cumulative daily spending for the selected month plotted against the previous month's full curve. This lets you see at a glance whether your current month's spending is tracking ahead of or behind last month.

The widget displays:
- Your current month's running total (in green) with a marker at today's date
- The previous month's spending curve (in gray) labeled with the actual month name (for example, "August 2026"). The x-axis spans the selected month's days; if the previous month was longer, its extra days are folded into the final visible point so the endpoint still equals the full previous-month total
- The total spent so far this month and the signed delta versus the previous month, both calculated over the same number of elapsed days so the comparison is always apples-to-apples. While the selected month is still in progress, the previous-month label names the day range being compared (for example, "Aug 1–8"). Once the selected month is complete, both months are compared in full.
- Gridlines with compact currency labels and a shared tooltip
- On narrow viewports, a compact date range (for example, "Sep 01 - 6, 2026") instead of the full date range, and x-axis tick labels for the selected month only so the chart stays uncluttered

**Selecting a month:** Use the month picker in the widget header to review any of the past 12 months. The widget's selected month is independent of the dashboard's global time period at the top of the page.

**Filtering by category:** A filter beside the month picker lists complete category groups with spending in the selected or previous month, plus groups containing a selected category. Uncategorized appears when it has spending or is selected. Selecting a parent includes its subcategories. Selecting every displayed option becomes unfiltered when every option belongs to a group with spending; a selected category with no spending keeps the filter active across months. Both chart lines and header totals use the selection. The button count reflects selected categories, counting children instead of also counting their parent. The selection is stored in the URL and carried through month changes and Customize mode.

The widget is hidden when there is no spending data for the selected month.

The debug event log at **Settings → Debug** records diagnostic events from background jobs and provider syncs.

### Expandable table view

The log table has an **expand** button in the card header (the same pattern used by the dashboard cashflow chart). ## Data exports

Sure allows you to export your financial data for backup or analysis purposes. When you create an export, the page automatically refreshes to show the latest status.

Only family admins can create and download exports. The web export feature redirects non-admins, while the API returns 403. Direct export-attachment requests without admin access to the owning family return 404.

### Export status tracking

The export list page automatically polls for updates when exports are in progress:
- **Processing exports**: The page checks for updates every 3 seconds
- **Completed exports**: Auto-refresh stops once all exports are complete
- **Download ready**: Download buttons appear when exports finish processing

This ensures you always see the current status without manually refreshing the page.

## Localization

Sure supports multiple display languages. You can change the interface language from **Settings → Preferences**.

### Country selector

The **Country** field in Settings → Preferences uses a searchable dropdown. Type a country name to filter the list instead of scrolling through the full list.

Supported languages: English, French, German, Spanish, Italian, Turkish, Norwegian Bokmål, Catalan, Romanian, Russian, Polish, Portuguese (Brazil), Portuguese (Portugal), Chinese (Simplified), Chinese (Traditional), Dutch, Hungarian, Vietnamese, and Ukrainian.

Navigation labels update to match your selected language. For example, the System health link in the Advanced section of the settings navigation appears as **Systemstatus** when the interface language is set to German. Super-admin-only navigation items follow the same localization as the rest of the interface.

The **Settings → Background Jobs** console is fully localized in German and Russian. This includes the worker status stats panel (Workers, Busy, Enqueued, Retries, Scheduled, Dead), the in-flight operations table columns, per-operation status labels (Running, Queued, Recent, Stuck), action buttons, and all confirmation and error messages. In German, the page title appears as **Hintergrundjobs** and the worker status section heading as **Worker-Status**. In Russian, the page title appears as **Фоновые задачи** and the worker status section heading as **Состояние обработчиков**.

The AI chat interface is fully localized in Brazilian Portuguese (pt-BR). This includes the AI greeting, suggested questions, chat navigation labels (all chats, start new chat, edit title, delete), the AI consent dialog, and error messages.

Several account page UI strings that previously failed to resolve in non-English locales now display correctly. The balance tooltip and "no balance data" message on account activity date rows, the selection toggle label in the activity feed, and the period picker's accessibility label all use the correct language when a non-English locale is set. Previously these strings rendered as raw translation-missing text or fell back silently to English.

### MXN number formatting in Spanish

When the interface language is set to Spanish, Mexican peso (MXN) amounts now display with US-style separators — a dot (`.`) as the decimal separator and a comma (`,`) as the thousands separator — matching how MXN values are natively formatted. Previously, the Spanish locale's European-style separators were applied to MXN, producing incorrect formats such as `1.234,56` instead of `1,234.56`. All other currencies continue to use the locale-aware separators for their respective locales.

### Date formatting across all locales

Dates that span multiple years — such as those shown in bills, the period picker, and transaction date pickers — now display in the correct format for your locale. Previously, only 7 of the 118 supported locales defined their own short-with-year date format. The other 111 fell back to the English format (`Jan 05, 2027`), so a German user, for example, would see `Jan 05, 2027` instead of `05. Jan 2027`. All 118 locales now have an explicit short-with-year format derived from their own long date format.

## Release highlights

When a new version of Sure is deployed, a "What's new" dialog appears the first time you interact with the app after the update. It shows the release notes for the deployed version so you can see what changed without leaving the app.

The dialog appears once per release, per account. Each release — including hotfix releases — is tracked separately, so a hotfix update triggers its own dialog even if you have already seen the base release. Dismissing it (by clicking **Done**, the close icon, the overlay, or pressing Escape) marks that release as seen and it will not reappear. Navigating away without dismissing does not mark it seen — the next page will offer it again.

The dialog is fetched lazily on your first click or keypress after the page loads, so it never interrupts the initial render. If a drawer or modal is already open when you first interact, the dialog waits until the page is clear before appearing.
