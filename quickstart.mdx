Get your Sure account up and running in three simple steps.

## 1. Create your account

Navigate to [localhost:3000](http://localhost:3000) and click **Sign Up**. Complete the setup screens to configure your login details and preferences.

## 2. Add your first account

Click **\+ Add Account** and select an account type:

- **Cash** for checking/savings accounts
- **Credit Card** for credit cards
- **Investment** for brokerage accounts
- **Loan** for mortgages or other debts

Enter your account name and current balance, then click **Create Account**.

## 3. Record a transaction

Go to **Transactions** in the sidebar and click **\+ New Transaction**. Choose a type:

- **Expense** for spending money
- **Income** for receiving money
- **Transfer** for moving money between accounts

Fill in the details and click **Add transaction**.

## Development setup

Want to contribute to Sure? Set up your local development environment.

Run the full test suite after setup to confirm everything is working:

```bash
bin/rails test
```

The suite should report zero failures and zero errors. If you are using the devcontainer, the PostgreSQL connection is configured with `username:` (the Rails-documented key), so no authentication errors should appear.

The devcontainer runs `pgvector/pgvector:pg16-trixie` as its database image rather than plain `postgres:16`. This is a drop-in replacement that ships the `vector` extension, which supplies the vector-storage prerequisite for document import. You still need to configure the chosen vector-store and embedding provider; PDF statement processing also requires a suitable AI provider.

After running `bin/setup`, you can optionally load demo data with:

```bash
rake demo_data:default
```

By default this appends a new demo family without touching existing data (`SKIP_CLEAR=1`). To wipe all existing data first and start fresh, set `SKIP_CLEAR=0`:

```bash
SKIP_CLEAR=0 rake demo_data:default
```

You can also pin the random seed to reproduce the same dataset across runs:

```bash
SEED=12345 rake demo_data:default
```

<Note>
Demo data is only available when running Sure in development mode, not in production or self-hosted deployments.
</Note>

### Design system previews

Sure uses [Lookbook](https://lookbook.build/) to render component previews. After starting `bin/dev`, open `/design-system` in your browser to browse and preview all `DS::*` components.

The preview routes are only available outside of production. If a preview returns an error, confirm you are running in development mode.

### Form action buttons

Use these conventions when adding action buttons to forms built with Sure’s `styled_form_with` helper:

- A form with one action ends in `f.submit`, which renders a full-width primary `DS::Button`. Do not pass `class:` to `f.submit` — it is ignored.
- A form with Cancel and a primary action ends in a right-aligned pair of natural-width buttons: Cancel (`variant: :secondary` or `:ghost`), then the primary (`type: :submit`). The variant carries the hierarchy, not the width.

```erb
<div class="flex justify-end gap-2">
  <%= render DS::Button.new(text: t(".cancel"), variant: :secondary, data: { action: "DS--dialog#close" }) %>
  <%= render DS::Button.new(text: t(".save"), type: :submit) %>
</div>
```

- Do not use `f.submit` in a pair — it is always full-width and ignores `class:`. Render the primary button explicitly with `type: :submit` instead.
- A destructive single action uses `DS::Button` with `full_width: true`, `type: :submit`, and `variant: :destructive` — `f.submit` always renders primary and cannot be used here.
- Keep the default button size. `size: :sm` text buttons are 28 px tall and the 44 px coarse-pointer target only applies to icon-only buttons.
- When a `DS::Dialog`'s buttons do not submit a form, use `dialog.with_action`. Pass `cancel_action: true` to make a button close the dialog.
- Amount inputs stay left-aligned. Use `numeric: true` for displayed figures. Inputs inside a column of figures, such as the budget grid, can also be right-aligned.
