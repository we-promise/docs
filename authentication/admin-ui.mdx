## Overview

The admin UI provides a comprehensive interface for managing SSO authentication providers. You can add, edit, disable, and remove providers without requiring server restarts or configuration file changes.

## Prerequisites

- `AUTH_PROVIDERS_SOURCE=db` environment variable configured
- `super_admin` access to the application
- Identity provider credentials (client ID, client secret, etc.)

## Accessing the admin UI

Navigate to the SSO providers management page in your admin dashboard:

```
https://your-domain.com/admin/sso_providers
```

## Managing providers

### Adding a new provider

<Steps>
  <Step title="Click Add Provider">
    Select the "Add Provider" button in the admin UI
  </Step>
  
  <Step title="Choose provider type">
    Select the authentication protocol:
    - OIDC (OpenID Connect)
    - OAuth2
    - SAML 2.0
  </Step>
  
  <Step title="Configure basic settings">
    Under **Basic Information**, enter the provider details:
    - **Name**: Unique identifier (lowercase, numbers, underscores only)
    - **Button Label**: Text shown to users on the login button (e.g. "Sign in with Keycloak")
    - **Icon**: Optional Lucide icon name for the login button
    - **Enable this provider**: Toggle to allow users to sign in with this provider
  </Step>
  
  <Step title="Enter credentials">
    Under **OAuth/OIDC Configuration**, add your identity provider credentials:
    - **Issuer URL** (OIDC): OIDC discovery endpoint
    - **Client ID** and **Client Secret** (OIDC/OAuth2)
    - **IdP Metadata URL** or manual certificate (SAML)
  </Step>
  
  <Step title="Set up user provisioning">
    Under **User Provisioning**, configure just-in-time provisioning:
    - **Default Role for New Users**: role assigned to JIT-provisioned accounts
    - **Group to Role Mapping**: optional IdP group-to-role mappings
  </Step>
  
  <Step title="Save and test">
    Save the provider configuration and test the login flow
  </Step>
</Steps>

### Editing an existing provider

<Steps>
  <Step title="Select the provider">
    Click on the provider you want to edit from the list
  </Step>
  
  <Step title="Update settings">
    Modify any configuration fields as needed
  </Step>
  
  <Step title="Save changes">
    Click "Save" to apply the updates immediately
  </Step>
</Steps>

<Note>
Changes to provider configuration take effect immediately without requiring a server restart.
</Note>

### Disabling a provider

You can temporarily disable a provider without deleting its configuration:

1. Navigate to the provider settings
2. Toggle the "Enabled" switch to off
3. Save the changes

Disabled providers will not appear on the login page, but their configuration is preserved.

### Deleting a provider

<Warning>
Deleting a provider will remove all its configuration. Users who authenticated with this provider will need to use alternative login methods.
</Warning>

To delete a provider:

1. Select the provider from the list
2. Click the "Delete" button
3. Confirm the deletion

## Provider configuration fields

### Common fields (all providers)

| Field | Description | Required |
|-------|-------------|----------|
| Name | Unique identifier (lowercase, numbers, underscores only) | Yes |
| Button Label | Text shown to users on the login button | Yes |
| Icon | Lucide icon name for the login button | No |
| Enable this provider | Whether the provider is active | Yes |

### OIDC-specific fields

| Field | Description | Required |
|-------|-------------|----------|
| Issuer URL | OIDC issuer/discovery endpoint | Yes |
| Client ID | OAuth2 client identifier | Yes |
| Client secret | OAuth2 client secret | Yes |
| Scopes | Space-separated list of scopes | No (default: `openid profile email`) |

### OAuth2-specific fields

| Field | Description | Required |
|-------|-------------|----------|
| Authorization URL | OAuth2 authorization endpoint | Yes |
| Token URL | OAuth2 token endpoint | Yes |
| User info URL | Endpoint to fetch user profile | Yes |
| Client ID | OAuth2 client identifier | Yes |
| Client secret | OAuth2 client secret | Yes |
| Scopes | Space-separated list of scopes | No |

### SAML-specific fields

| Field | Description | Required |
|-------|-------------|----------|
| SP Callback URL (ACS URL) | Configure in your IdP as the Assertion Consumer Service URL | Yes |
| IdP Metadata URL | URL to your IdP's SAML metadata; auto-configures other fields | No |
| IdP SSO URL | SAML single sign-on endpoint (manual config) | Conditional |
| IdP SLO URL | SAML single logout endpoint (optional) | No |
| IdP Certificate | X.509 certificate in PEM format | Conditional |
| NameID Format | Email address, persistent, transient, or unspecified | No |

## Testing provider configuration

After configuring a provider, test the integration:

<Steps>
  <Step title="Open test login">
    Click the "Test Login" button in the provider settings
  </Step>
  
  <Step title="Authenticate">
    Complete the authentication flow with your identity provider
  </Step>
  
  <Step title="Verify user data">
    Check that user attributes are correctly mapped
  </Step>
  
  <Step title="Confirm role assignment">
    Verify that roles are assigned based on your mapping configuration
  </Step>
</Steps>

## Best practices

<AccordionGroup>
  <Accordion title="Use descriptive provider names">
    Choose clear names like "Google Workspace" or "Okta Corporate" instead of generic names like "OIDC Provider 1"
  </Accordion>
  
  <Accordion title="Test before enabling">
    Always test a provider configuration before enabling it for all users
  </Accordion>
  
  <Accordion title="Keep credentials secure">
    Store client secrets and private keys securely. The admin UI encrypts sensitive fields in the database.
  </Accordion>
  
  <Accordion title="Monitor audit logs">
    Regularly review SSO audit logs to detect authentication issues or security concerns
  </Accordion>
  
  <Accordion title="Document custom mappings">
    Keep documentation of your group-to-role mappings for future reference
  </Accordion>
</AccordionGroup>

## Troubleshooting

### Provider not appearing on login page

- Verify the provider is enabled in `/admin/sso_providers`
- Check that `AUTH_PROVIDERS_SOURCE=db` is set
- Restart the application if you recently changed the environment variable

### Authentication fails

- Verify all endpoints are correct and accessible
- Check that client ID and secret match your identity provider
- Review audit logs for specific error messages
- Ensure redirect URIs are configured in your identity provider

### Users not getting correct roles

- Review your role mapping configuration
- Check the group claims sent by your identity provider
- Verify attribute mappings are correct
- Test with a known user account
