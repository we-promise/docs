Wise integration connects your Wise multi-currency account to Sure using a personal API token. Sure syncs your currency balances, Jars (savings pots), transfers, card payments, and activity directly from the Wise API — no OAuth flow required.

See [Transaction history and import limits](/providers/transaction-history) for initial sync defaults, history limits, and options for older transactions.

## How it works

1. You create a personal API token in Wise and paste it into Sure
2. Sure fetches the profiles (personal and/or business) available to that token
3. You choose which profile(s) to connect — each becomes its own connection in Sure
4. Sure discovers every currency balance and Jar under the connected profile(s)
5. You link each discovered balance to a new or existing Sure account
6. Syncs then run automatically, pulling balances, transfers, card payments, and Jar activity

## Setting up Wise

1. Sign in to your Wise business account at [wise.com](https://wise.com) (personal API tokens are issued from business account settings, even if you're only connecting a personal profile)
2. Go to **Settings → Connect and manage apps → Developer tools → API tokens** (requires two-factor authentication on the account)
3. Create a new personal API token and choose an access level: **read only** lets Sure read balances, transfers, and activity; **full** additionally allows the token to authorize recipients and transfers, so prefer read-only unless you need that capability elsewhere
4. In Sure, go to **Settings > Providers**, find the **Wise** panel, and paste the token
5. If the token has access to more than one profile (for example, a personal and a business profile), select which ones to connect — Sure creates a separate connection for each
6. Open **Set Up Accounts** on the new connection and link each currency balance to a Sure account
7. To enable full transaction history including incoming payments, complete the [SCA setup](#strong-customer-authentication-sca) below

<Note>
For testing, Wise provides a sandbox environment at `https://api.wise-sandbox.com` (the V2 sandbox host; the legacy `api.sandbox.transferwise.tech` URL was retired). Set `WISE_BASE_URL` in your Sure environment to point at it instead of the default live API (`https://api.wise.com`).
</Note>

## Features

### Multi-currency balances

- **Standard balances**: one balance per currency held in your Wise account, refreshed (including reserved amount) on every sync
- **Jars (savings pots)**: synced alongside standard balances and mapped to a savings-type account in Sure
- New balances discovered on a sync are shown as "needs setup" until linked to a Sure account
- A balance that no longer appears in Wise for two syncs in a row is marked as closed and frozen; if Wise lists it again, it becomes active again

### Transaction syncing

Sure fetches transactions using per-source coverage windows rather than a fixed lookback. Each source (transfers, activities, statements) tracks the range it has successfully covered and starts the next sync from there, so no transactions are skipped between syncs.

- The first sync imports history from the date you configure (or a default number of days back); later syncs extend coverage incrementally from the last successful fetch
- On a complete full-history import, a balance account opens at 0 on the day before Wise created the balance
- Transfers, card payments, cash withdrawals, direct debits, refunds, and other single-leg activities are all imported
- Transactions are routed to the specific balance they belong to — a payment in one currency no longer appears on balances in other currencies
- Cross-currency conversions are imported as a debit on the source balance and a credit on the target balance, each with the amount in the correct currency
- Outgoing transfer fees are calculated from the gross debit (what left the balance) rather than Wise's `sourceValue` field, so the fee line reflects the actual cost
- If a sync fetch fails partway through (for example, due to a network error or Wise rate limit), Sure records which sources arrived in full and retries the rest on the next sync; the connection card shows a sync summary with any fetch failures

### Card payments and activity

Without balance statements (available on personal tokens in some regions and SCA-enabled business accounts), the Wise activity feed is the source for card payments, refunds, cash withdrawals, and direct debits.

- Card payments, cash withdrawals, direct debits, refunds, cashback, and rewards are imported from the activity feed when statements are not available for a balance
- Each activity is booked on the balance that paid or received it
- Split payments (where Wise charges across multiple balances) are resolved by replaying each balance's history to determine the exact amount each balance contributed; the split is shown per balance
- When statements become available for a balance (after SCA is configured), activity-feed transactions are matched to their statement counterparts and renamed in place, preserving any categories, notes, or links you set

### Jar activity

- Deposits and withdrawals to a Jar are imported as "Transfer to Jar" / "Transfer from Jar" transactions
- Interest and Wise Assets fees are imported automatically
- Transfers between a standard balance and a Jar are automatically linked as Sure Transfers, so the same movement is never double-counted as separate income and expense

### Multiple profiles

If your Wise account has both personal and business profiles, you can connect several profiles from the same token at once. Each profile is a separate connection that can be synced, updated, or disconnected independently.

## Strong Customer Authentication (SCA)

Wise requires Strong Customer Authentication on the balance-statement endpoint. SCA uses an RSA keypair: Sure signs a one-time challenge with the private key, and Wise verifies it against the public key you register in your Wise account.

Without SCA, Sure falls back to the transfers and activity feed. This fallback covers outgoing transfers, card payments, and most activity types, but incoming bank payments into your Wise account details may be missing. Configuring SCA adds the statement endpoint, which provides a complete transaction history.

<Note>
In some regions, personal API tokens cannot access the statement endpoint at all — Wise returns 403 without an SCA challenge. Sure detects this and treats the balance as statement-unavailable rather than reporting it as a sync failure. The transfers and activity fallback continues to run for those balances.
</Note>

### Enabling SCA

<Warning>
SCA keypair generation requires Active Record encryption to be configured. On a self-hosted instance that has not set the `ACTIVE_RECORD_ENCRYPTION_*` environment variables or a `SECRET_KEY_BASE`-derived equivalent, the **Generate SCA keypair** button will return a validation error. See [encryption keys for bank sync](/self-hosting#encryption-keys-for-bank-sync) in the self-hosting guide before proceeding.
</Warning>

1. In Sure, go to **Settings > Providers** and open the Wise panel for the connection
2. Click **Generate SCA keypair** — Sure creates a 2048-bit RSA keypair and stores the private key encrypted at rest
3. Copy the public key that appears in the panel
4. In Wise, go to **Settings → Connect and manage apps → Developer tools → Public keys → Add public key** and paste the public key
5. Run a sync — the statement endpoint should now succeed and incoming payments will be imported

<Warning>
Generating a new keypair does not automatically revoke the previous public key in Wise. If you regenerate the keypair in Sure (for example, after a key rotation), remove the old public key from Wise manually and register the new one.
</Warning>

### Troubleshooting SCA

**Incoming payments are missing**: SCA is not yet configured or the public key has not been registered with Wise. Follow the steps above. In some regions, personal tokens cannot access statements regardless of SCA — the transfers and activity fallback will still import card payments and outgoing transfers.

**Statement fetch fails after configuring SCA**: confirm the public key in Wise matches the one shown in the Sure Wise panel. If the key was regenerated, the old public key must be removed from Wise and the new one registered.

## Limitations

- Uses a Wise personal API token rather than OAuth; the token carries whatever account access you grant it in Wise
- Wise Assets (investment) balances are not tracked as accounts — only fees charged against them are imported
- Each discovered currency balance must be linked to a Sure account manually after the first sync; balances aren't created automatically
- Incoming bank payments into your Wise account details only sync after [SCA is configured](#strong-customer-authentication-sca) (except in regions where the statement endpoint is unavailable to personal tokens)
- Outgoing transfers funded by a card or external bank (rather than from your Wise balance) are identified as externally funded; the debit for those does not appear on any Wise balance in Sure

## Troubleshooting

**"No Wise connection configured" error**: If you see this alert when trying to add a Wise account, Sure could not find an active Wise connection for the request. The selected connection may have been removed; this alert is not itself a token-validity check. Go to **Settings > Providers > Wise**, paste your personal API token, and save before adding accounts.

**Invalid token / connection requires update**: your API token was revoked, is invalid, or lacks permissions (Wise personal API tokens don't expire on their own). When Wise rejects the token with a 401 or 403, Sure marks the connection as requiring an update and the sync fails — the connection card shows a **Reconnect** prompt instead of a green "Connected" status. Create a new personal token in Wise and update it in the Wise provider panel.

**No profiles found**: the token doesn't have access to any Wise profile. Check the token's permissions in Wise and try again.

**A currency balance is missing**: run a sync, then check **Set Up Accounts** on the connection — new balances only become Sure accounts once you link them.

**Incoming payments are missing**: the balance-statement endpoint requires SCA. Follow the [SCA setup steps](#strong-customer-authentication-sca) to generate a keypair and register the public key with Wise.

**Transactions appear on the wrong balance**: this affected multi-currency accounts on older syncs. Run a fresh sync — Sure now routes each transaction to the specific balance it belongs to and removes any incorrectly routed entries.

**Connection appears under Available instead of Your connections**: after a successful setup, the Wise panel should move to the "Your connections" section of **Settings → Providers** and show a status pill, sync button, and last-synced line. If it stays in Available, the connection was not saved. Re-enter the API token and save again.

**Sync shows fetch failures**: if a sync could not retrieve all data (for example, due to a Wise API error), the connection card shows which sources failed. Sure keeps the previously stored data and retries the failed sources on the next sync, so no transactions are lost.
